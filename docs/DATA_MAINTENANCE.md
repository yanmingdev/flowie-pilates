# 日常資料維護

一般內容可透過 Flowie 管理後台或 Supabase Table Editor 更新。資料表結構、RLS、trigger、索引與函式變更必須以新的 SQL migration 版控。不要以 Table Editor 直接修改 `student_packages.balance`、`credit_ledger`、預約或出勤狀態；使用後台業務操作或受保護 RPC，才能維持帳本一致。

| 想修改的項目 | 管理方式 | 關聯／注意事項 |
|---|---|---|
| 分店 | 資料管理 → 分店；或 `branches` | 停用不會刪除歷史場次。 |
| 教室與容量 | 資料管理 → 教室；或 `rooms` | 名額取場次上限與最新教室容量較小者；不可縮到低於已有的未來預約人數。 |
| 教室可使用時間 | 資料管理 → 教室可使用時段；或 `room_availability` | 未設定啟用時段時不限制排課；修改不會重寫既有場次，歷史使用率會依目前設定重算。 |
| 老師 | 資料管理 → 老師；或 `teachers` | 老師註冊後提供 User ID，填入 `profile_id`；同步老師角色。設定老師分店、課程資格及可授課時段後才可排課。 |
| 老師請假／代課 | 資料管理 → 老師請假；行事曆修改場次老師 | 請假若與已有場次衝突，先安排代課或取消場次。 |
| 課程、分類、圖片 | 資料管理 → 課程／課程分類；或 `courses`／`course_categories` | 已排場次的名稱跟隨課程資料；預約當下堂數取課程當時設定，已扣除的堂數不追溯。圖片可先上傳至 Supabase 的 `studio-public/<studio UUID>/...`，再填入公開網址。 |
| 時段 | 行事曆 | 單次或每週；可修改單一／後續場次。已有預約的場次不得直接更動課程或時間；取消會依交易退堂。 |
| Banner | 資料管理 → 首頁 Banner；或 `banners` | 啟用且排序較前的 Banner 優先顯示；支援圖片網址、標題、副標題及 https／站內連結。 |
| 首頁文字、順序、顯示 | 資料管理 → 首頁區塊；或 `homepage_sections` | 固定元件搭配資料設定，不能儲存並執行任意 JavaScript。主視覺文字依序採 Banner、區塊、網站設定的值。 |
| 聯絡資訊 | 資料管理 → 網站設定；或 `site_settings` | Email 與電話會顯示在網站頁尾。 |
| 預約截止 | 行事曆 → 編輯場次 | 可設定開放與截止時間；留空則開課時截止，截止時間不得早於開放時間或晚於開課。 |
| 取消期限 | 資料管理 → 預約規則；或 `booking_settings.cancellation_hours` | 個別場次若有指定取消期限，優先使用該場次設定；已建立預約保留當時的取消期限。 |
| 方案及適用課程 | 資料管理 → 課程方案／方案適用課程 | 不適用全部課程的方案，須設定 `package_courses`。 |
| 學生方案、餘額 | 資料管理 → 學生與方案指派 | 以指派與調整操作寫帳本；不直接編輯餘額。可查詢學生預約、出勤與堂數紀錄。 |

後台儲存成功會使 React Query 資料失效並重新讀取；在 Supabase 直接修改資料後，重新整理頁面或等待查詢重新取得。可見名額僅供參考，提交時仍由資料庫重新驗證。停用已有場次的老師、教室或課程不會自動取消既有預約；若需退款，應先在行事曆取消場次。
