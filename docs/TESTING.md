# V1.2 測試結果與限制

環境：Linux、Node.js 24、PGlite、本機 PostgreSQL 15、PostgREST 16.5。資料庫與測試帳號均為隔離的臨時資料；Auth／Storage 使用測試替身。本次沒有 Docker、沒有你的 Supabase 專案或憑證，未在託管 Supabase 實際登入或操作。

## 現有範圍

- 品牌管理員可管理該品牌所有分店；**尚無限制單一或指定分店的管理員授權**。若需此功能，須新增分店權限資料模型並完整修改與測試 RLS／RPC，不能用前端隱藏代替安全控制。
- 預約截止時間可按場次設定，空值表示開課時截止；取消期限另行設定並於預約時快照。教室使用率依目前的可用時段計算，修改設定可能改變歷史區間的結果。
- 學生與老師先註冊 Auth；後台可加入已註冊帳號，不能替未註冊者建立 Auth 帳號。SQL seed 不含使用者和交易；`db:demo` 有本機限定的帳號／交易初始化腳本，但未在真實 Supabase 執行。少量歷史紀錄是本機事後補建的示範資料。
- 圖片需先透過 Dashboard／Storage 上傳後填 URL，後台沒有檔案上傳按鈕；公開 bucket 不存私人資料。
- 授課紀錄單次最多 1000 筆，學生預約與帳本最多 200 筆；其他查詢可能受 Supabase 最大列數影響。大資料量應設計完整伺服器分頁。
- 沒有自動將過去場次轉為 `completed` 的排程，跨日授課未支援；沒有線上付款。
- 新安裝 SQL 只適用空白專案；既有資料庫需先備份與設計遷移。上線前完成真實服務整合、安全審查與備份還原驗收。
